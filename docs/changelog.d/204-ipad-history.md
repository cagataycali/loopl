- **History's delete flow is now verified on an iPad, and the four tests that said it was broken were wrong four different ways** (IMPROVE-9). The full UI suite had never run on a tablet until this week, and when it did, all four `HistoryUITests` failed on the screen that deletes someone's conversations — with `kAXErrorCannotComplete … kAXScrollToVisibleAction`, a message that names a scroll and reads like a flake. The element it could not scroll to was 36 pt wide and 0 pt tall at `{417, 611}`: the exact centre of the iPad, which is where the invisible ⌘Y proxy button lives. `keyboardShortcut` keeps that proxy in the accessibility tree even through `.accessibilityHidden(true)`, it carries the label *History* like the real control, and `app.buttons["History"].firstMatch` had been picking it — so every one of the four tests died on a button nobody can see, before reaching the screen under test. Behind it were three more phone-shaped assumptions: that the iPad's sidebar toggle is ours (it is Apple's, and ships with no identifier at all), that the navigation bar states *“3 selected”* (the sidebar's bar has `Cancel` and `Select all` leading and the toggle trailing, so UIKit drops the title — the count survives on the **Delete 3** button, which is the one that matters), and that History always offers *Select* (on an empty archive, offering nothing is the correct behaviour being tested). A sixth failure in the same family blamed ⌘Y on every iPad while probing for a sidebar section header that does not exist; with a probe that can actually succeed, ⌘Y works. **Nothing in History was broken on an iPad** — select, select all, the count, the confirmation, the delete, the empty state and Cancel all behave — but nothing had been proving it. One shared `reachHistory()` now opens History correctly on either shape, and a failure prints the buttons that were on screen instead of the word *scroll*.
