- **Switching models no longer needs room for both in memory** (build 43). Picking a second model used to load it while the first was still resident, so the peak of every switch was both models at once — and iOS kills an app at a memory ceiling (about 5 GB on an 8 GB iPhone) even when either model alone fits. That is why a switch between two models that each ran fine could end the app without a word. The current model is now let go first, then the next one is read from disk; your downloads are the library, memory holds one. If the new model fails to load, the previous one comes back from disk and the line under the chat says what went wrong; if that reload fails too, the banner says both. A switch while the model is still answering is refused, the same way the other buttons that would disturb an answer are, with a line that says to wait and pick again. `EngineSwitchOrderTests` pins the order (unload, load, and on failure reload), the refusal, and the two failure messages.
