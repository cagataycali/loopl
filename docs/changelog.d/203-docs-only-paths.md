- **A documentation change stopped spending an hour of build machines** (SUPERVISOR-12, found by watching my own merge). `ci` and `ui` each carry a list of paths that should not start them, so editing the docs does not occupy a macOS runner — and the previous change (the changelog fragments above) added two docs-only files that were in **neither** list: the new docs pull-request workflow and the release script that folds fragments together. Merging it therefore started a full `ci` run **and** a two-device `ui` run to verify a changelog: about **80 minutes of build machines for zero bytes of app**. The minutes are not the real cost — `ui` keeps only one queued run at a time, so a pointless run can take the slot the next real app change needed, which is the same starvation that once left that guard with a single green run in its first fourteen. Both lists now cover the new paths, and the set lives in **one** place (`scripts/check-workflows.sh`, which `ci` already runs) with the two workflows checked against it, so forgetting an entry is a red build instead of a silent hour. Checked by breaking it on purpose three ways — removing the two new entries names exactly those two, deleting a whole list names all six, a malformed workflow is still caught — and it immediately caught a slip of my own during the test, when restoring one file from git quietly took my fix with it.
