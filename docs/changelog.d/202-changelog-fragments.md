- **A pull request no longer edits the one line every other pull request edits** (SUPERVISOR-12, acting on a measurement from two lanes). Every entry on this page was added directly under `## Unreleased`, which made that heading the only thing two concurrent branches both had to touch: one lane hit **6 conflicts in 6 pull requests, every one on this file and on nothing else**, and each cost a resolution, a force-push and a full CI re-run on the one file in the diff nobody reads while reviewing. The real risk was not the minutes — a conflict resolved in a hurry is how a `<<<<<<<` marker reaches a merge commit, which is why merging has needed a grep for markers as a guard. A branch now writes `docs/changelog.d/<pr>-<slug>.md`, a file no other branch has, and a mkdocs hook splices the fragments into the Unreleased section as the site builds, newest pull-request number first; the page a reader sees is unchanged, and the fragment files are dropped from the built site so they never become stray pages. `scripts/changelog-release.py` folds them into this file under a dated version heading at release time, which is the only moment anybody edits it. The hook carries a dependency-free self-test that runs in the docs workflow before the strict build, and it was checked against four deliberately broken versions of itself — ascending order, splicing below the existing bullets, a missing heading passing silently, and the directory's README published as an entry — each of which it caught.
