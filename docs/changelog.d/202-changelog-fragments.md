- **A pull request no longer edits the one line every other pull request edits**. Every entry on this page was added directly under `## Unreleased`, which made that heading the only thing two concurrent branches both had to touch: one lane hit **6 conflicts in 6 pull requests, every one on this file and on nothing else**, and each cost a resolution, a force-push and a full CI re-run on the one file in the diff nobody reads while reviewing. The real risk was not the minutes — a conflict resolved in a hurry is how a `<<<<<<<` marker reaches a merge commit, which is why merging has needed a grep for markers as a guard. A branch now writes `docs/changelog.d/<pr>-<slug>.md`, a file no other branch has, and a mkdocs hook splices the fragments into the Unreleased section as the site builds, newest pull-request number first; the page a reader sees is unchanged, and the fragment files are dropped from the built site so they never become stray pages. `scripts/changelog-release.py` folds them into this file under a dated version heading at release time, which is the only moment anybody edits it. The hook carries a dependency-free self-test that runs in the docs workflow before the strict build, and it was checked against four deliberately broken versions of itself — ascending order, splicing below the existing bullets, a missing heading passing silently, and the directory's README published as an entry — each of which it caught.
- **A docs change is now proven before it reaches `main`, not after**. Nothing ever built the site on a pull request: `docs.yml` runs on pushes to `main` only, because it is a *deploy* pipeline — it holds `pages: write`, sits in the `pages` concurrency group with cancel-in-progress and ends in a deployment, so simply adding pull requests to it would let a branch cancel `main`'s in-flight deploy and then try to publish itself. A separate deploy-free `docs-pr` workflow now builds the site strictly on any pull request that touches `docs/`, `mkdocs.yml` or either docs workflow, with read-only permissions and a per-branch concurrency group; social cards and the DocC reference stay on `main`, which still builds the real site. This was not a hypothetical gap: the fragment mechanism above went through review with a landmine in it, and only a hand-run of the adjacent script found it — **a fragment naming a test suite, which nearly every real changelog entry does, turned `docs/check_symbols.sh` red**, because that script skips `changelog.md` (release notes legitimately name things that live in `Tests/`, not `Sources/`) and knew nothing of the new directory. The first lane to write a normal entry would have reddened the docs job on `main` and stopped the site updating. `changelog.d/` is now skipped the same way — and only for the symbol scan, so the copy rules still hold there. Checked by watching it fail and then pass: a fragment naming `EngineArchiveTests` fails before the fix and passes after, a bogus type on a real docs page still fails, and a fragment using the product name the docs copy rule bans still fails that rule.
